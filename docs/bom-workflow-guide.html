What bom.yaml does

This workflow combines a customer bill of materials with a Priority workbook, optionally enriches parts from SQL Server and SAP, and creates an annotated Excel workbook with BOM and debug sheets.

Read two inputsReconstruct groupsApply PCB scopeCheck vendorsEnrich partsChoose MAIN / SUBWrite XLSX
Steps execute top to bottom on a current table. save keeps a named dataset; it does not write an Excel file. The final output section writes the workbook.

01 · Read the two workbooks

Customer BOM → parts

The first worksheet is read. Studio searches the first 15 rows for a header with at least four recognized titles. Aliases such as “part no” and “quantity” map to canonical fields. Missing matches use the fallback columns below; if no header qualifies, the standard layout applies. Cells are trimmed and rows with all selected fields blank are skipped.

FieldsFallback Excel columns
Level, PartNumber, PartType, DescriptionA, B, C, D
Rev, Qty, UOMI, Z, AA
FindNum, RefDesAC, AD
MfgName, MfrPNAZ, BA

Priority → priorities

The Priority workbook must contain a sheet named Shortage. It reads column A as ForthPN and M as Value, beginning at row 168. A missing sheet stops the workflow.

Keys are trimmed and uppercased with norm. Values 1, 1.0, 01, P1, and 01.0 become numeric P1. Other values use parseFloat; zero and non-numeric values mean no priority. Empty keys are removed; when a normalized key repeats, the last row wins.

For HTTP uploads, the priority filename is matched by the case-insensitive expression prio|shortage. CLI and Studio use explicit input identifiers bom and priority.

02 · Reconstruct component groups

Alternate manufacturer rows often leave repeated component fields empty. Eff* columns carry forward the last nonblank Level, PartNumber, PartType, Description, Rev, Qty, UOM, and FindNum.

  • HasAG: at least one original component field from Level through UOM is populated. These names describe the logical output layout, not the input’s physical columns.
  • HasIJK: RefDes, MfgName, or MfrPN is present. A later PCB rewrite also sets this flag.
  • Level0: only the first processed row with the exact Level string “0” gets this flag. It does not exclude every row whose level is zero.

GroupID starts at 1. It increases when the effective find number changes. Before a find number exists, each row with HasAG starts a new group. Noncontiguous runs of the same find number can therefore have different GroupIDs.

Reference and quantity repair uses a window grouped by EffFindNum, not GroupID. A blank RefDes takes the first nonblank reference in that find-number group. A zero or unparseable effective quantity takes the group’s largest positive quantity, or “1” if none exists. Nonzero quantities, including negative values, remain unchanged.

03 · Establish PCB scope and revision

A description is checked in both its original and effective forms. After trimming and uppercasing, pieces are split at comma, semicolon, colon, slash, pipe, or backslash. A piece must start with PCB followed by a non-alphanumeric character or the end of the piece. “PCB assembly” matches; “PCBA” does not.

The last detected PCB row becomes the scope boundary. Rows after it remain in the output but are excluded from enrichment and MAIN/SUB selection. If no PCB is detected, every row is in scope. Carried-down descriptions can cause continuation rows to count as PCB rows too.

For an in-scope PCB, use MfrPN, otherwise PartNumber, otherwise EffPartNumber as the base. Append _REV_ plus the first whitespace-separated revision token when both exist. If the base already contains that exact suffix, it is left unchanged.

Base: BOARD-123     Revision: A released
Reformatted MfrPN: BOARD-123_REV_A

The original MfrPN is retained as OrigMfrPN for output outside scope.

04 · CFT-001: decide which vendors are forbidden

Brand names and descriptions are normalized. Leading non-alphanumeric characters are removed from the manufacturer part-number key used for these exceptions.

Brand ruleAllowed exception
TDK word match or brand starts with TDKDescription does not start CAP, or MPN starts CGA
Brand contains SAMSUNG or SEMCODescription does not start CAP, or MPN matches ^CL(.{6}|.{10})P
Exact YAGEO CORPORATION, WALSIN TECHNOLOGY CORPORATION, KDSNo exception defined

The Samsung pattern means CL, followed by exactly six or ten arbitrary characters, then P; further trailing characters are allowed. Other brands are not forbidden by this rule. All forbidden flags are limited to in-scope rows.

TDK and Samsung exemptions also allow non-CAP descriptions. Their log-message wording is narrower than the actual expression. Use the expressions above to understand the rule.

05 · Look up Forth part numbers and SAP data

SQL Server · controlled by db_enabled

Covered means in scope, not Level0, and HasIJK. Nonblank manufacturer part numbers become normalized lookup keys. The query reads MaterialNo, ZBlock, and Maker from SAP_ForthFacDb.dbo.Material_Master, limited to project FNS - Finisar and ZBlock <> 'D'.

Master rows with empty Maker are removed, and normalized duplicate Makers keep the first result. PCB rows without a primary hit can use a second lookup with _SANMINA appended. If the retry succeeds, that manufacturer part number is used in the output.

A covered row with no match gets CREATE P/N, unless forbidden, in which case that fallback becomes blank. Existing matches can remain visible even when forbidden. Uncovered rows get no Forth part number. When the database is disabled, all lookup hits are empty. SQL errors log a warning and continue with fallback values.

SAP REST · controlled by sap_enabled

Only in-scope, non-Level0 rows with HasIJK, an allowed vendor status, and a real Forth part number are queried. Unique sorted material numbers are batched. Defaults are 50 materials and 3 extra retries when configuration values are absent or invalid.

The request posts to http://{sap_host}:{sap_port}/api/sap-rfc/call with WERKS and MATNR data, optional configured tcode, and a hard-coded employee_id: "106049". This is separate from the upload’s bam field.

Responses supply status, vendor name/code, and stock. Material keys are indexed with and without leading zeros; the last duplicate response wins. Status prefers the first truthy value of mmsta, mstae, zblock, status. Stock uses labst when non-null, otherwise stock.

A Z1 flag from SQL remains true even if SAP later supplies a different status. Failed SAP batches log and are skipped; they do not necessarily fail the entire workflow.

06 · CFT-002: choose MAIN and alternates

Priority values join by normalized ForthPN, not manufacturer part number. Eligibility excludes rows in this order: below PCB scope, Level0, no HasIJK, Z1 blocked, then forbidden without an exemption.

Within each GroupID and normalized ForthPN, only the first eligible occurrence is a candidate. Blank ForthPN and CREATE P/N are exempt from duplicate suppression. A group with no candidates has no MAIN.

First applicable rule wins

  1. Exactly one P1 candidate: select it.
  2. P1 candidates with a vendor: select their highest stock.
  3. P1 candidates without a vendor match: select the highest stock among P1 candidates.
  4. No P1, but a vendor exists: select the first vendor candidate. Stock does not decide this rule.
  5. No P1 or vendor, positive stock exists: select highest stock.
  6. Otherwise: select the first candidate.

Ties go to the top-most candidate. Remaining candidates become SUB1, SUB2, … in their existing group order. Excluded duplicates and ineligible rows get a diagnostic reason instead.

HasVendor uses trimmed VName, or VendorCode when the name is empty, and rejects the exact strings empty, “0”, “None”, and “-”. Vendor presence is not a case-insensitive validation rule.

07 · Read the BOM and debug sheets

The final table is saved as result. The BOM sheet presents effective component fields, manufacturer details, a separator, Block Status, Forth P/N, and Priority. It freezes the header and adds a thick bottom border at the last in-scope row of each group.

Visual markerMeaning
Yellow rowIn-scope Level0 header/component row
Yellow Forth P/N cellCREATE P/N, unless forbidden or Z1 without an exemption
Red manufacturer cellsForbidden or Z1, without an exemption
Blue PriorityMAIN
Green PrioritySUB alternate
Black PriorityDuplicate Forth P/N excluded from selection

debug inherits the BOM columns and styles, then adds P1 value, SAP vendor name/code, stock, internal Forth material number, eligibility, decision reason, and GroupID. Start with Eligibility Status and Decision Reason when a row was not selected.

An exemption can suppress red highlighting, but Z1 still makes a row ineligible. Color alone does not prove eligibility. Rows outside scope are retained with original MfrPN and blank visible enrichment fields; their debug eligibility explains the exclusion.

08 · Run the actual workflow

Offline CLI example

From the repository root with Go installed:

go run ./cmd/migo -in bom=testdata/bom_basic.xlsx -in priority=testdata/prio_basic.xlsx -out out.xlsx workflows/bom.yaml

Default CLI configuration disables database and SAP enrichment. This validates file processing and fallback rules, but does not reproduce live material, vendor, stock, or P1 outcomes. Use -check instead of keeping an output file when needed.

In Mai Studio

Open the repository workspace, load workflows/bom.yaml, validate, then bind bom and priority to the fixture paths above. Use Advanced YAML for the nested branches and expressions that visual editors preserve but cannot fully edit. Desktop runs are offline; live SQL and REST operations are unavailable.

Through the configured service

curl --fail -F files=@testdata/bom_basic.xlsx -F files=@testdata/prio_basic.xlsx -F bam=113280 http://localhost:3081/api/bom/upload
curl --fail -o bom-output.xlsx http://localhost:3081/api/bom/download

The service must already be running with the intended configuration. Download returns the latest result for the workflow. Open the actual XLSX in Excel to inspect formatting; Studio’s preview shows cell values.

09 · Inspect the complete YAML

Embedded from the repository file used to write this explanation. Expand to inspect the exact rules.

Show workflows/bom.yaml
# BOM processor: a customer BOM plus a Priority workbook in, the annotated
# BOM (BOM + debug sheets) out. Every rule is in this file; the steps are the
# generic ones described in docs/WORKFLOWS.md.
#
# POST /api/bom/upload   files: Customer BOM + Priority (any order), bam: employee number
# GET  /api/bom/download latest result of this workflow
name: BOM
input:
  bom: {label: Customer BOM}
  priority: {label: Priority, match: "(?i)prio|shortage"}

steps:
  # ---- read the customer BOM ------------------------------------------------
  # First sheet. The header row is the first of the top 15 rows where at least
  # 4 columns carry a known title; otherwise the standard layout applies.
  - from:
      input: bom
      header:
        search: 15
        min: 4
        columns:
          Level: [level, lvl, item level]
          PartNumber: [part number, part no, item number, internal pn, p/n]
          PartType: [part type, type, category]
          Description: [description, desc, part description]
          Rev: [rev, revision, item rev]
          Qty: [bom.qty, qty, quantity, bom qty]
          UOM: [bom.uom, uom, unit of measure, unit]
          FindNum: [bom.find num, find num, find no, find, line item, item]
          RefDes: [bom.ref des, ref des, reference designator, designator, refdes]
          MfgName: [manufacturers.mfg name, mfg name, manufacturer, mfr name, maker, vendor]
          MfrPN: [manufacturers.mfr. part number, manufacturers.mfr part number, mfr part number, mfr. part number, mpn, mfr pn]
        fallback: {Level: A, PartNumber: B, PartType: C, Description: D, Rev: I, Qty: Z, UOM: AA, FindNum: AC, RefDes: AD, MfgName: AZ, MfrPN: BA}
      trim: true
      skip_blank: true
      empty: The selected BOM file is empty.
  - save: parts

  # ---- read the Priority workbook: Forth P/N (A) -> priority (M), from row 168
  - fail:
      when: '"Shortage" not in sheets("priority")'
      message: Priority workbook has no sheet named "Shortage"
  - from: {input: priority, sheet: Shortage, columns: {ForthPN: A, Value: M}, start: 168}
  - set:
      Key: norm(ForthPN)
      # 1, 1.0, 01, P1 mean P1; otherwise the number (0 and non-numbers: none)
      P: 'norm(Value) in ["1", "1.0", "01", "P1", "01.0"] ? 1 : (parseFloat(Value) == 0 ? nil : parseFloat(Value))'
  - filter: Key != ""
  - dedupe: {by: [Key], keep: last}
  - log: Loaded {len(rows)} Priority entries.
  - save: priorities

  # ---- groups ---------------------------------------------------------------
  - from: parts
  - set:
      HasAG: '!blank(Level) || !blank(PartNumber) || !blank(PartType) || !blank(Description) || !blank(Rev) || !blank(Qty) || !blank(UOM)'
      HasIJK: '!blank(RefDes) || !blank(MfgName) || !blank(MfrPN)'
      Level0: index == 0 && Level == "0"
      # Effective values: the row's own, else carried down from above.
      EffLevel: Level
      EffPartNumber: PartNumber
      EffPartType: PartType
      EffDescription: Description
      EffRev: Rev
      EffQty: Qty
      EffUOM: UOM
      EffFindNum: FindNum
  - fill: [EffLevel, EffPartNumber, EffPartType, EffDescription, EffRev, EffQty, EffUOM, EffFindNum]
  # A new group starts when the find number changes (or, before any find
  # number, on every row with A-G data).
  - set:
      GroupID: 'index == 0 ? 1 : prev("GroupID") + (EffFindNum != "" ? (prev("EffFindNum") != EffFindNum ? 1 : 0) : (HasAG ? 1 : 0))'
  - window:
      by: [EffFindNum]
      set:
        # a blank ref des takes the first one of its find number
        EffRefDes: 'RefDes != "" ? RefDes : first(filter(group, #.RefDes != ""))?.RefDes ?? ""'
        # a zero quantity becomes the find number's largest, or 1
        EffQty: >-
          toNumber(EffQty, 0) != 0 ? EffQty :
          (let m = max(map(group, toNumber(#.EffQty, 0)));
           m > 0 ? first(filter(group, toNumber(#.EffQty, 0) == m)).EffQty : "1")

  # ---- PCB scope and reformat --------------------------------------------------
  # A PCB row: a description piece (split at , ; : / | \) starting with "PCB"
  # not followed by a letter or digit.
  - set:
      IsPCB: 'any([Description, EffDescription], {any(splitAny(norm(#), ",;:/|\\"), {trim(#) matches "^PCB([^A-Z0-9]|$)"})})'
  # Rows below the last PCB row are out of scope.
  - set: {LastPCB: 'IsPCB ? index : index == 0 ? -1 : prev("LastPCB")'}
  - window: {set: {InScope: 'let end = last(group).LastPCB; end < 0 || index <= end'}}
  # In-scope PCB rows: the MPN becomes <MPN, else part number>_REV_<first word of rev>.
  - set:
      OrigMfrPN: MfrPN
      RevToken: 'first(fields(Rev != "" ? Rev : EffRev)) ?? ""'
      NewMfrPN: >-
        let base = MfrPN != "" ? MfrPN : (PartNumber != "" ? PartNumber : EffPartNumber ?? "");
        InScope && IsPCB && base != "" && RevToken != ""
          ? (base contains "_REV_" + RevToken ? base : base + "_REV_" + RevToken)
          : MfrPN
  - log:
      when: 'any(rows, #.NewMfrPN != #.MfrPN)'
      message: 'Reformatted Column K for {len(filter(rows, #.NewMfrPN != #.MfrPN))} PCB row(s).'
  - set:
      HasIJK: HasIJK || NewMfrPN != MfrPN
      MfrPN: NewMfrPN

  # ---- CFT-001: forbidden vendors ----------------------------------------------
  - set:
      Brand: norm(MfgName)
      MPNKey: 'replaceRe(norm(MfrPN), "^[^A-Z0-9]+", "")'
      Desc: 'norm(blank(EffDescription) ? Description : EffDescription)'
      # Brands that are banned unless the row is allowed:
      Exception: >-
        Brand matches "\\bTDK\\b" || Brand startsWith "TDK" ? "TDK" :
        Brand contains "SAMSUNG" || Brand contains "SEMCO" ? "SAMSUNG" : ""
      Exempt: >-
        Exception == "TDK" ? (Desc not startsWith "CAP" || MPNKey startsWith "CGA") :
        Exception == "SAMSUNG" ? (Desc not startsWith "CAP" || MPNKey matches "(?s)^CL(.{6}|.{10})P") :
        false
      Forbidden: >-
        InScope && (Exception != "" ? !Exempt :
          Brand in ["YAGEO CORPORATION", "WALSIN TECHNOLOGY CORPORATION", "KDS"])
  - log:
      when: 'any(rows, #.InScope && #.Exception == "TDK" && #.Exempt)'
      message: 'TDK Exception: {len(filter(rows, #.InScope && #.Exception == "TDK" && #.Exempt))} TDK CAP (CGA series) row(s) confirmed valid.'
  - log:
      when: 'any(rows, #.InScope && #.Exception == "SAMSUNG" && #.Exempt)'
      message: 'Samsung Exception: {len(filter(rows, #.InScope && #.Exception == "SAMSUNG" && #.Exempt))} Samsung MLCC (CL...P...) row(s) confirmed valid.'
  - log: 'CFT-001: {len(filter(rows, #.Forbidden))} row(s) flagged as forbidden.'

  # ---- Forth P/N from Material_Master (SQL Server) ------------------------------
  # Rows looked up: in scope, not level 0, with I-K data. PCB rows that miss
  # are tried again with _SANMINA appended.
  - set:
      Covered: InScope && !Level0 && HasIJK
      LookupKey: norm(MfrPN)
      RetryMfrPN: 'MfrPN == "" || norm(MfrPN) endsWith "_SANMINA" ? MfrPN : MfrPN + "_SANMINA"'
      RetryKey: 'IsPCB ? norm(RetryMfrPN) : ""'
  - if: truthy(config("db_enabled"))
    then:
      - sql:
          connection: db
          query: |
            SELECT MaterialNo, ISNULL(ZBlock, '') AS ZBlock, Maker
            FROM SAP_ForthFacDb.dbo.Material_Master
            WHERE ZBlock <> 'D' AND Project = 'FNS - Finisar'
              AND UPPER(LTRIM(RTRIM(Maker))) IN (@mpns)
          params:
            mpns: >-
              uniq(concat(
                map(filter(rows, #.Covered && #.MfrPN != ""), #.LookupKey),
                map(filter(rows, #.Covered && #.MfrPN != "" && #.RetryKey != ""), #.RetryKey)))
          columns: [MaterialNo, ZBlock, Maker]
          on_error: 'WARNING: MSSQL connection/lookup failed ({error}) -- skipping DB lookup and using fallback Forth P/N.'
          save: master
      - save: parts
      - from: master
      - filter: '!blank(Maker)'
      - dedupe: {by: [Maker], keep: first, normalize: true}
      - save: master
      - from: parts
      - join: {with: master, on: [LookupKey], right_on: [Maker], normalize: true, take: {HitMaker: Maker, HitNo: MaterialNo, HitZ: ZBlock}}
      - join: {with: master, on: [RetryKey], right_on: [Maker], normalize: true, take: {RetryMaker: Maker, RetryNo: MaterialNo, RetryZ: ZBlock}}
    else:   # no database: nothing is found, every looked-up row asks for a new P/N
      - set: {HitMaker: nil, HitNo: nil, HitZ: nil, RetryMaker: nil, RetryNo: nil, RetryZ: nil}
  - set:
      Lookup: Covered && MfrPN != ""
      UseRetry: Lookup && HitMaker == nil && IsPCB && RetryMaker != nil
      Found: Lookup && (HitMaker != nil || UseRetry)
      ForthPN: >-
        !Covered ? "" :
        MfrPN == "" ? (Forbidden ? "" : "CREATE P/N") :
        (let pn = Found ? str(UseRetry ? RetryNo : HitNo) : "CREATE P/N";
         Forbidden && pn == "CREATE P/N" ? "" : pn)
      BlockStatus: 'Lookup && Found ? str(UseRetry ? RetryZ : HitZ) : ""'
      Z1: norm(BlockStatus) == "Z1"
      MfrPN: 'UseRetry ? RetryMfrPN : MfrPN'
      VName: '""'
      VendorCode: '""'
      Stock: '0'

  # ---- block status, vendor and stock from SAP (REST) -----------------------------
  - if: truthy(config("sap_enabled"))
    then:
      - set:
          SapRow: 'InScope && !Level0 && HasIJK && (!Forbidden || Exempt) && ForthPN not in ["", "CREATE P/N"]'
      - if: '!any(rows, #.SapRow)'
        then:
          - log: 'SAP enrichment: no eligible Forth P/N rows to query.'
        else:
          - rest:
              url: 'http://{config("sap_host")}:{config("sap_port")}/api/sap-rfc/call'
              method: POST
              each: 'sort(uniq(map(filter(rows, #.SapRow), #.ForthPN)))'
              # whole numbers from config; 0, missing or invalid: the default
              batch: 'let f = parseFloat(str(config("api_batch_size"))) ?? 0; f >= 1 && f < 1e9 ? int(f) : 50'
              retries: 'let f = parseFloat(str(config("api_retries"))) ?? 0; f >= 1 && f < 1e9 ? int(f) : 3'
              body: >-
                let data = concat([{WERKS: config("sap_werks")}], map(batch, ({MATNR: #})));
                config("sap_tcode") == nil
                  ? {employee_id: "106049", DATA: data}
                  : {tcode: config("sap_tcode"), employee_id: "106049", DATA: data}
              # the answer is a list, {tables: [{rows: [...]}]}, or a list under DATA, data or rows
              rows: >-
                type(response) == "array" ? response :
                type(response) != "map" ? [] :
                type(response.tables) == "array" ? flatten(map(response.tables, type(#) == "map" && type(#.rows) == "array" ? #.rows : [])) :
                type(response.DATA) == "array" ? response.DATA :
                type(response.data) == "array" ? response.data :
                type(response.rows) == "array" ? response.rows : []
              keys: lower
              columns: [matnr, mmsta, mstae, zblock, status, vname, lifnr, labst, stock]
              on_error: 'WARN: SAP batch {batch_number} failed after {retries} retries: {error}'
              save: sap
          - save: parts
          # One answer per material number, with and without leading zeros (the last answer wins).
          - from: sap
          - filter: truthy(matnr)
          - set:
              K1: norm(str(matnr))
              K2: 'norm(replaceRe(trim(str(matnr)), "^0+", ""))'
              SapStatus: 'trim(str(coalesce(mmsta, mstae, zblock, status) ?? ""))'
              SapVName: 'truthy(vname) ? trim(str(vname)) : ""'
              SapVCode: 'truthy(lifnr) ? trim(str(lifnr)) : ""'
              SapStock: toNumber(labst ?? stock, 0)
          - stack: {columns: [K1, K2], into: Key}
          - dedupe: {by: [Key], keep: last}
          - save: sap
          - from: parts
          - set:
              PN1: norm(ForthPN)
              PN2: 'norm(replaceRe(norm(ForthPN), "^0+", ""))'
          - join: {with: sap, on: [PN1], right_on: [Key], take: {A_Hit: Key, A_Status: SapStatus, A_VName: SapVName, A_VCode: SapVCode, A_Stock: SapStock}}
          - join: {with: sap, on: [PN2], right_on: [Key], take: {B_Hit: Key, B_Status: SapStatus, B_VName: SapVName, B_VCode: SapVCode, B_Stock: SapStock}}
          - set:   # rows found in SAP take its status, vendor and stock; Z1 blocks
              SapHit: SapRow && (A_Hit != nil || B_Hit != nil)
              SapStatus: 'A_Hit != nil ? A_Status : B_Status'
              SapZ1: 'SapHit && norm(SapStatus != "" ? SapStatus : BlockStatus) == "Z1"'
              BlockStatus: 'SapZ1 ? "Z1" : SapHit && SapStatus != "" ? SapStatus : BlockStatus'
              Z1: Z1 || SapZ1
              ForthPN: 'SapZ1 && ForthPN == "CREATE P/N" ? "" : ForthPN'
              VName: 'SapHit ? (A_Hit != nil ? A_VName : B_VName) : VName'
              VendorCode: 'SapHit ? (A_Hit != nil ? A_VCode : B_VCode) : VendorCode'
              Stock: 'SapHit ? (A_Hit != nil ? A_Stock : B_Stock) : Stock'
          - log: 'SAP enrichment: matched {len(filter(rows, #.SapHit))} / {len(filter(rows, #.SapRow))} rows.'

  # ---- CFT-002: one MAIN per group, the other candidates SUB1, SUB2... ---------------
  - set:
      PKey: norm(ForthPN)
  - join: {with: priorities, on: [PKey], right_on: [Key], take: {PV: P}}
  - set:
      PriorityValue: 'InScope ? PV : nil'
      Eligible: >-
        !InScope ? "Ineligible (Below PCB Scope)" :
        Level0 ? "Ineligible (Level 0)" :
        !HasIJK ? "Ineligible (No I,J,K)" :
        Z1 ? "Ineligible (Z1 Blocked)" :
        Forbidden && !Exempt ? "Ineligible (CFT-001 Forbidden)" :
        "Eligible"
      HasVendor: 'let v = trim(VName) != "" ? trim(VName) : trim(VendorCode); v not in ["", "0", "None", "-"]'
      VendorLabel: 'VName != "" ? VName : VendorCode'
      # A Forth P/N used twice in a group: only the top-most row stays a candidate.
      DupKey: 'norm(ForthPN) == "CREATE P/N" ? "" : norm(ForthPN)'
      Dup: 'false'
  - window:
      by: [GroupID, DupKey]
      where: Eligible == "Eligible"
      set: {Dup: DupKey != "" && index > 0}
  - set:
      Candidate: Eligible == "Eligible" && !Dup
  - pick:
      by: [GroupID]
      where: Candidate
      mark: Main
      reason: Reason
      rules:   # the first rule with matching rows decides; ties go to the top-most row
        - rows: PriorityValue == 1
          when: size == 1
          reason: 'MAIN (Cond A: Single P1 match)'
        - rows: PriorityValue == 1 && HasVendor
          best: Stock
          reason: 'MAIN (Cond B: Multiple P1 & Vendors -> Highest Stock: {best} [{tied > 1 ? str(tied) + " tied, top-most: " : ""}{chosen.VendorLabel}])'
        - rows: PriorityValue == 1
          best: Stock
          reason: 'MAIN (Cond B: Multiple P1, No Vendor -> Highest Stock: {best} [{tied} tied, top-most])'
        - rows: HasVendor
          reason: 'MAIN (Cond C: No P1 -> Vendor match [{chosen.VendorLabel}, top-most])'
        - rows: 'true'
          best: Stock
          when: best > 0
          reason: 'MAIN (Cond C: No P1, No Vendor -> Highest Stock: {best} [{tied} tied, top-most])'
        - rows: 'true'
          reason: 'MAIN (Cond D: No P1, No Vendor, No Stock -> Fallback top-most row)'
  - set:
      Priority: 'Main == true ? "MAIN" : ""'
  - window:
      by: [GroupID]
      where: Candidate && Main != true
      set:
        Priority: '"SUB" + str(index + 1)'
        Reason: '"SUB" + str(index + 1) + " (Alternate in group)"'
  - set:
      Reason: >-
        !InScope ? "Out of Scope" :
        Eligible != "Eligible" ? Eligible :
        Dup ? "Duplicate Forth P/N (excluded from MAIN/SUB)" : Reason
  - log: 'CFT-002: assigned MAIN to {len(filter(rows, #.Main == true))} group(s).'
  - window:   # the last row of each group gets a thick bottom border
      by: [GroupID]
      where: InScope
      set: {GroupEnd: index == size - 1}
  - save: result
