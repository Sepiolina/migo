01 / Getting ready

A workspace starts here.

Build the desktop app from source, then open the repository as your first workspace.

Install the native prerequisites

Use a native PowerShell window for the Windows desktop app. Open a new terminal after installing these tools.

Prepare a Linux desktop environment

Install Go 1.22+, Node.js 22 LTS or newer supported LTS, Git, Rust stable, and a C/C++ toolchain. The native app needs a desktop display session.

On Ubuntu, install WebKitGTK 4.1 and GTK 3 development libraries, librsvg, libayatana-appindicator3-dev, patchelf, and pkg-config. Package names vary by distribution.

Follow Tauri’s Linux prerequisites ↗

Prepare the macOS native toolchain

Install Git, Go 1.22+, Node.js 22 LTS or newer supported LTS, and stable Rust. Follow Tauri’s official macOS instructions for Xcode and native development tools.

Follow Tauri’s macOS prerequisites ↗

Get the source & launch

git clone https://github.com/Sepiolina/migo.git
cd migo/apps/studio
npm ci
npm run desktop:dev

Already have the checkout? From the repository root, start with cd apps/studio. First launch compiles dependencies and may take several minutes. Keep the terminal open; Ctrl+C stops the development app.

02 / Your first workflow

From five orders to two totals.

Follow the bundled Customer order totals example. Click each stage to see what changes.

Interactive walkthrough
Customer order totalsIllustrated fixture · not a live run

Do it in Mai Studio

  1. Open the repository root as the workspace. In Project & inputs, choose + New workflow → Customer order totals.
  2. Follow the connected chain in Blocks. In Workbook setup, confirm input orders and output sheet Totals referencing saved table totals.
  3. Choose Validate. Bind orders to examples/orders.xlsx in Project & inputs.
  4. Choose Run workflow. Inspect Excel data → Output workbook → Totals. Expect Acme = 50 and Beta = 5; row order may vary.
  5. Save to an unused path such as workflows/customer-totals.yaml.

The same workflow, in YAML

This is the bundled examples/orders-totals.yaml. Open it through Open path as an alternative to choosing the template.

name: Customer order totals
input:
  orders: {label: Orders workbook}
steps:
  - from: {input: orders, sheet: Orders, trim: true}
  - filter: num(Quantity) > 0
  - set:
      Line total: num(Quantity) * num(col("Unit price"))
  - group: {by: [Customer], sum: [Line total]}
  - save: totals
output:
  sheets: {Totals: totals}

Start with “Copy a worksheet”

  1. Choose + New workflow → Copy a worksheet.
  2. In Workbook setup, keep input parts and make the output reference saved table result. Choose Apply workbook settings.
  3. Set Read source to parts; enter a sheet name or leave it blank for the first sheet. Sheet numbers start at 1.
  4. Set Save dataset as to result. Validate, bind parts to examples/parts.xlsx, then run.

Keep names connected

Input identifiers in Workbook setup must match Read source blocks. Output sheets refer to saved table names, so Save dataset as must use the same name.

Input: partsRead: partsSave: resultOutput: result

Renaming an input or table does not update matching blocks automatically. Finish connected blocks and required fields, and apply or discard setup drafts before saving, running, switching views, or closing.

04 / Make it real

Validate. Bind. Run. Inspect.

A successful run creates a real XLSX file inside your workspace.

  1. Validate the workflow. The Go parser checks the current document. Read status-bar errors and fix them. Validate again after changing input declarations.
  2. Bind every input. In Project & inputs → Input files, use workspace-relative paths to existing workbooks, such as examples/orders.xlsx.
  3. Run workflow. Studio runs the current editor contents. Saving is a separate action. Complete or discard drafts first.
  4. Inspect the workbook. Successful runs open Excel data. Choose an Input tab or Output workbook, select a sheet, and use Previous / Next to page through rows.

Read the result with confidence

Click a cell for its full value; Clear dismisses the inspector. Expand data gives the panel more room, Dock panel restores it, and Close returns to authoring.

Generated files live under .studio/runs/. The output path and SHA-256 identify the artifact. Open that XLSX in Excel to check styling and formula metadata; the preview shows cell values.

Changed something? Workflow or binding edits mark output stale. Run again. Workbook edits outside Studio are not detected automatically; rerun after those too.

Workbook saved; preview unavailable means the file was generated successfully. Open the displayed output path in a spreadsheet app.

Prefer the command line?

Run the same bundled example without a desktop or service. Execute this from the repository root with Go installed.

go run ./cmd/migo -in orders=examples/orders.xlsx -out outputs/customer-totals.xlsx examples/orders-totals.yaml
05 / Keep your work

Save once. Reuse with new inputs.

Your workflow definition and your session’s input bindings are separate.

Open & save workflows

Open a workflow… discovers YAML files recursively under workflows/. Use Open path → Open workflow path for another relative YAML path, including examples/orders-totals.yaml.

Set Save path and choose Save workflow, or press Ctrl/Cmd+S. For a new file or a copy, use an unused path and create its parent folder outside Studio first.

Files must be UTF-8 YAML (.yaml or .yml), at most 1 MiB. Absolute paths, .. traversal, and symlinks in workflow paths are rejected. Reopen the workspace to refresh discovery after adding files externally.

Reuse the customer totals workflow

Copy a workbook into your workspace. Preserve the Orders sheet and the Customer, Quantity, and Unit price headers, or update the corresponding blocks.

Bind orders to the new relative path and rerun. Bindings are session settings; supply them again when reopening. Inputs must be real XLSX or Excel 97–2003 BIFF8 XLS files. Password-protected files, older XLS variants, and renamed CSV/HTML files are unsupported.

Save before closing. There is no autosave or recovery store. A dot and “Unsaved” mark edits. Choose Keep editing in a discard dialog to retain your work.
06 / Beyond your desktop

Package for a Linux service.

Build a deployment ZIP from a full, trusted source checkout. This is separate from a desktop installer.

  1. Prepare the source. Open the complete repository containing go.mod, go.sum, and cmd/maiservice. Install Go on PATH. The first build may download Go modules. A workflow-only folder cannot build the service.
  2. Save everything first. Save workflow edits and apply or discard pending settings. The builder reads config and workflows from disk.
  3. Open Build Linux package. Select amd64 or arm64, a saved relative config.json path, workflow overrides, and deployment settings. Defaults are /opt/maiservice, service maiservice, and port 3081.
  4. Select a security mode. Secure signs the inventory and encrypts config for a server age public recipient. Trusted local is explicitly unsigned with plaintext configuration.
  5. Build ZIP package. Keep the window open; cancellation is unavailable. Find the ZIP at .studio/packages/package-*/mai.zip. Check its hash, inventory, and reported validation status.
Secure mode. Create a signing identity in Studio; its private key stays in the OS credential store. Generate the server’s age identity once and copy only its public age1… recipient into Studio. Keep that server identity protected and retain the signing public key independently.
Deployment boundaries. Overrides add or replace endpoints; they are not an endpoint allowlist. ELF checks and cross-compilation do not prove target runtime behavior. The installer requires a new target; it cannot upgrade an existing installation.

Verify before extracting or running anything

Obtain the verifier from an independently trusted checkout and confirm the signing public key through a trusted channel outside the ZIP. With Python 3 and OpenSSL 3 on the server:

python3 scripts/verify-mai-package.py --trusted-key 'BASE64_PUBLIC_KEY_FROM_STUDIO' mai.zip

Replace the placeholder with the trusted public key. Only extract after verification succeeds. Intentionally unsigned packages use --allow-unsigned, which checks integrity and inventory without signer authenticity.

Follow the complete package installation guide ↗ for server age setup, extraction, a dedicated service account, PM2, and health checks. Confirm you are reading the guide for your checkout’s branch. Keep configuration secrets and generated packages out of source control.

07 / When you get stuck

A clear next step.

Common symptoms, what they mean, and how to get moving again.

Native commands are disabled, or Studio only opened in a browser.

Launch npm run desktop:dev from apps/studio and use the native Tauri window. Open a workspace through Project & inputs. Browser preview alone cannot access folders or run workflows.

The Go sidecar cannot start.

Check that Go is installed on PATH, or set MAI_GO to its executable. Install stable Rust and Cargo, then restart npm run desktop:dev so the runner rebuilds for your host.

An input workbook cannot be read.

Confirm the file exists inside the selected workspace. Bind the declared input identifier to its workspace-relative path. Check the sheet name, file format, and whether the workbook is password-protected. Revalidate after changing input declarations.

Saving, running, or switching views is blocked.

Connect and complete draft blocks or discard block edits. Apply or discard workbook setup and step-inspector changes. Correct invalid fields before applying. Use Advanced YAML for unsupported settings after resolving pending drafts.

A save reports that the file changed on disk.

Studio retains your editor contents. Preserve them using a new, unused Save path, then reopen the original to compare external changes. There is no merge dialog or force-overwrite control. An existing file cannot be overwritten by saving a copy to its path.

“Workbook saved; preview unavailable” appears.

Execution succeeded and the XLSX was retained. Open the displayed workspace-relative output path in Excel; its SHA-256 still identifies the artifact. Preview currently limits XLSX files to 25 MiB compressed and 64 MiB expanded. The runner response budget can also limit embedded previews.

The output looks old after changing the workbook.

Run again. Workflow and input-binding edits mark output stale, but changes to workbook files outside Studio are not tracked automatically. Verify that the binding points to the intended file and inspect the new output artifact.

Linux reports missing GTK or WebKit packages.

Install the platform-specific Tauri v2 prerequisites, including WebKitGTK 4.1 and GTK 3 development libraries. A missing gdk-3.0 or WebKit pkg-config package indicates absent native development libraries. Starting the native window also requires a desktop session.

Can I use live SQL / REST, cancel a run, or inspect intermediate traces?

Desktop execution currently runs offline Excel fixtures. External SQL/REST, intermediate execution traces, cancellation controls, and live desktop connections are planned. Use the repository’s current capabilities documentation to check progress.
